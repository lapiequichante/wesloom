# 0031. Shader text lives in template files; generators fill holes

Date: 2026-09-12

Status: Accepted

Amends [ADR 0028](0028-lighting-models-dispatched-by-a-g-buffer-id.md):
the generated shading function and lighting pass keep their generators,
but the *text* moves out of Rust string literals into files.

## Context

ADR 0028 moved `shading.wxsl` and the lighting pass from hand-written
modules into Rust generation, because the one thing that varies with the
lighting set — a call inside the light loop — cannot be named by a fixed
shipped module. The cost was real: roughly 120 lines of readable WXSL
became `format!` templates with `\n\` line continuations and doubled
braces, and that translation produced more bugs per line than anything
else in the milestone (macro redeclarations, escaping mistakes, an
unresolved `MODEL_ID_SCALE`). It also violated the repo's own best
structural decision (ADR 0020, "the file is the truth"): a shader author
can no longer read the shading function as shader.

## Decision

The fixed shader text lives in `.wxsl` template files under
`wxsl-core/templates/lighting/`, embedded with `include_str!` and filled
at generation time by `wxsl_core::template::fill`:

* `macros.wxsl` — the three `@macro` declarations the generated text
  carries (or a material module already declares);
* `dispatch_direct.wxsl` — the one-model dispatch;
* `dispatch_switch.wxsl` — the `ModelExtras` struct and the `switch`
  over the id (holes for the per-model fields and arms);
* `shade_surface.wxsl` — the debug-normals variant and the whole shading
  function: light loop, shadow lookup, ambient, exposure, tonemap,
  encoding (holes for the dispatch call's shape and the extras);
* `lighting_pass.wxsl` — the pass: G-buffer bindings, fullscreen
  triangle, the unpack function, the depth-based background test and the
  context assembly (holes for bindings, the unpack's shape, the loads).

Holes are `${NAME}` — a spelling no WGSL uses, so no escaping. `fill` is
strict in both directions: a table entry with no hole in the file, and a
hole with no table entry, are generator bugs that fail loudly at
generation time rather than emitting half-filled shader for the compiler
to reject three layers later. The generator keeps the *logic* — which
models, which targets, which ids, which imports — and owns one table of
hole → text per template. The generated output carries the provenance
header ("generated by `wxsl_core::lighting`; do not edit") as before.

The rule this buys, stated as a guard rail: **logic in Rust, text in
files.** A generator that owns more than its holes has taken text that
belongs in a template. (`gbuffer_struct` and `pack_gbuffer` stay in
Rust: they are loops over layout entries with per-target expressions —
logic-dense, text-thin.)

## Alternatives considered

* **`@expect fn` in WXSL** — a required symbol the mounting root
  provides, the inverse of an import, so `shading.wxsl` could stay one
  full file and only the dispatch be generated. This is the cleaner end
  state but touches `wxsl-lang`'s resolver; the template mechanism does
  not preclude it, and the holes can migrate to `@expect` later, hole by
  hole.
* **Keep `format!` but factor it better.** Still text in Rust strings,
  still unreadable as shader, still escaping-prone; rejected for the
  reason the ADR exists.

## Consequences

* The generated output is inspectable and diffable as shader; editing
  the light loop no longer means editing a Rust string literal. The
  corpus gate (ADR 0029) checks every template's filled output in about
  a second, so a template typo fails with a WXSL diagnostic, not a GPU
  panic.
* Adding a shader-level feature to the shading function is now: edit the
  template, add or extend a hole if the feature needs generation-time
  input. Adding a lighting model touches no template at all.
* `wxsl-core` now carries `.wxsl` files. They are not shipped modules —
  `wxsl-stdlib`'s module table is untouched, and the registry's
  `is_abi_module` filter is unaffected — they are generator inputs, and
  `templates/` is where that distinction lives.
